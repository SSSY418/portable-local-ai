# 便携本地 AI 工作台

**中文** | [English](README.en.md) 

一个插到任何 Windows 电脑上就能用的本地 AI 工作台。模型和程序都在这个文件里，
不装到系统、不写注册表，拔盘就走。

---

## 一、怎么用

> **⚠️ 如果你是从 GitHub clone 下来的，第一次要多做一步：先把环境下下来。**
> 便携版 Python 已经在仓库里，但 koboldcpp（719 MB）和模型不在，要下载：
> ```
> powershell -ExecutionPolicy Bypass -File _tools\install.ps1
> ```
> 约 1 分钟。下完再按下面的步骤用。已经下过的文件会自动跳过，所以重复跑没关系。

1. 把移动盘插到电脑上（USB 3.0 的口更快）。
2. 打开 `portable-ai` 文件夹，**双击 `启动.bat`**。
3. 会弹出一个黑窗口，先启动模型服务，再自动打开浏览器。
   - **第一次启动比较慢**（要解包程序、把模型读进内存），请耐心等，别关窗口。
   - 这个窗口就是"电源开关"：**用完了直接关掉它**，模型服务会跟着一起退出。
4. 浏览器里会出现四个入口：

| 入口 | 干什么 |
|---|---|
| **对话** | 跟本地模型聊天、写东西，字是一个一个往外蹦的 |
| **模型管家** | 看有哪些模型、当前用的是哪个，点一下换模型（要等 1~4 分钟） |
| **写小说** | 按模板建小说、直接在里面看和改大纲与正文 |
| **体检** | 一键检查 CPU、内存、显卡、磁盘，最后给一句人话结论 |

> 全程离线。除了第一次下载模型，不需要联网，聊的内容也不会离开这台电脑。

### 首页还能"说人话"

首页最下面那个输入框，可以直接说：

```
帮我看看电脑卡不卡
现在用的是哪个模型
有哪些模型可以选
```

**流程是「先翻译、给你看、你确认、才执行」**，不是模型说啥就干啥：

1. 本地模型把这句人话翻译成「调哪个功能、带什么参数」；
2. 页面上显示给你看（比如：要执行 `modelctl` 的 `switch` `<某个模型文件名>`）；
3. 你点「确认执行」才真的动手；点「取消」就什么都不做。

这样做是因为本地模型不大，偶尔会翻译错。**参数最终由后端再校验一遍**
（技能必须是登记过的、模型文件必须真实存在、不许带路径），所以最坏情况只是"翻译错了"，
不会让它乱动你的文件。

### 关于"系统提示词"和"思考模式"

- **系统提示词默认是空的**，程序不会替你塞任何设定，模型就按自己的习惯回答。
  想让它有固定人设（比如"你是武侠小说作者"），点对话页的**设置**填进去就行。
- **思考模式默认关闭**。有些新模型默认会先自言自语想一大段再回答，
  写东西时白等还白烧算力，所以默认关掉。
  技术细节：关掉时程序会在暗地里塞一句 `/no_think`（实测有效，
  而 `chat_template_kwargs` 那种写法在这版 koboldcpp 上无效）。
  想让它先想再答，就打开"设置"里的思考模式开关，并且把"最长回复"调大一些。

### 启动参数（可选）

在双击 `启动.bat` 之前，可以先在同一个窗口敲 `set` 来改：

```bat
set PORTABLE_AI_GPULAYERS=12      :: 给显卡的层数，少给点更稳
set PORTABLE_AI_BACKEND=vulkan    :: 换另一个后端（默认 cuda）
set PORTABLE_AI_MODEL=别的模型.gguf :: 指定用哪个模型
set PORTABLE_AI_MAXWAIT=600       :: 等模型加载的总上限（秒，默认 300）
启动.bat
```

不想敲命令的话，也可以直接改 `启动.bat` 里那几行的默认值。

### 启动要等多久

**先说最快的一条路：那个黑窗口别关。**

| 情况 | 从按下列能用 |
|---|---|
| 模型服务还在跑（窗口没关） | **约 1.4 秒** |
| 冷启动（窗口关过） | **约 126 秒** |

用完浏览器标签页随便关，模型还留在内存里；下次双击 `启动.bat` 会看到
「检测到端口 5001 上已经有模型服务在跑，直接用它」，秒进。只有确定今天不再用了才关窗口。

冷启动那一百多秒花在三件事上：

1. **解包** koboldcpp 自带的运行库（约 600 MB，单文件程序的固有点开销，约 32 秒）
2. **读模型** 由实际大小决定（这个 USB 盘实测 40~97 MB/s，一般2-3G的模型约 40~60 秒）
3. **上传权重到显存 + 建 KV 缓存**

> 想再快只能从硬件下手：
> **加内存**（内存至少要能装下整个模型文件，系统才能把它缓存住，
> 之后第二次加载接近瞬时 —— 实测缓存命中比读盘快约 20 倍）；
> 或者**把模型放内置固态**（读 2 GB 级模型只要几秒，但会失去"拔盘就走"）。

启动提示是这样设计的：

- 到 **120 秒**还没好，会明确告诉你一声：`已经等了 120 秒，还在读模型，继续等…`
- 然后**继续等**，直到 **300 秒**（`PORTABLE_AI_MAXWAIT` 可调）才算失败
- 进程要是自己崩了/退了，会立刻放弃，不干等
- 真失败了才会去试另一个后端 —— 但在慢盘上另一个后端**并不会更快**，
  所以"多等一会儿"比"换后端重来"划算得多

> 为什么不做"卡死检测"：试过用 CPU 判断（没用，加载时 CPU 长时间不动、
> 实测第 30 秒到第 105 秒一直停在 15.4 秒），也试过用"内存+显存变化"判断，
> 结果把正常加载的进程误判成卡死、提前掐掉，反而更糟。所以现在就是简单可靠地等。

## 二、这里面都有什么

```
portable-ai\
  bin\            koboldcpp.exe（CUDA 版）、koboldcpp_nocuda.exe（Vulkan/CPU 版）· 未包含，首次要下载
  models\         gguf 模型 · 未包含，需要自己放
  py\             便携版 Python 3.12（只用了标准库，没装任何第三方包）· 已包含
  app\
    workbench.py  工作台后端（Python 标准库 http.server）
    launcher.py   找 koboldcpp / 启动 / 等就绪 / 停服务（技能和启动器共用）
    web\          index.html  chat.html  status.html  model.html  novel.html
    skills\       status.py（体检）、modelctl.py（模型管家）、
                  switcher.py（后台换模型）、router.py（说人话翻译）、skills.json
  novels\         小说作品；模板\ 里是样板
  work\           技能唯一允许读写文件的地方（换模型状态、测速缓存也在这）
  _tools\         start.ps1（启动器逻辑）、install.ps1（补下大文件）、put.ps1
  启动.bat        双击这个
  README.md       就是本文件
```

> **`py\`（便携版 Python，21 MB）已经在仓库里**，clone 下来就有。
>
> **`bin\`（koboldcpp，719 MB）和 `models\`（模型）不在仓库里，首次要自己下载。**
> 原因：`bin\` 里单个文件就 607 MB，超过 GitHub 的 100 MB 限制；走 Git LFS 虽然能传，
> 但会占满它的免费额度（1 GB 存储 / 每月 1 GB 流量），别人多 clone 几次就超了。
> 所以改成让脚本从**官方地址**下载（走公共带宽，不占任何人的额度）。
>
> ```
> # 第一次使用，clone 之后跑一次（约 1 分钟，下载 719 MB）
> powershell -ExecutionPolicy Bypass -File _tools\install.ps1
>
> # 顺便连模型一起下（自己给地址）
> powershell -ExecutionPolicy Bypass -File _tools\install.ps1 `
>     -ModelUrl "https://hf-mirror.com/<仓库>/resolve/main/<文件名>.gguf"
>
> # 模型也可以自己下好任意 .gguf，直接丢进 models\ 目录
> ```
>
> 已经下载过的文件会自动跳过，所以这条命令重复跑也不会重复下载。

## 三、怎么加模型

1. 找一个 **gguf** 格式的模型文件（`.gguf` 结尾），放进 `models\` 文件夹。
2. 去「模型管家」点一下换过去，或者重启 `启动.bat`。

程序会自动挑 `models\` 里**按名字排序第一个** gguf 当默认模型。
想指定用哪个，就用上面说的 `PORTABLE_AI_MODEL`。

**注意 FAT32 的 4 GB 上限**：如果移动盘是 FAT32，**单个文件不能超过 4 GB**。
大于 4 GB 的模型文件根本拷不进来（会报"空间不足"，其实是格式上限，不是真没空间）。

**注意显存**：给显卡多少层（`--gpulayers`）要按**你这台机器的显存**来定。
默认值是 **22 层**，在一台 4 GB 显存的机器上实测占约 2.5 GB，留了安全余量。

> ⚠️ **不要随便把 `--gpulayers` 调到很大。** 实测把它调到全部层都塞显卡时，
> 显存被榨干，Windows 直接蓝屏，停止代码 `0x0000010E`
> （VIDEO_MEMORY_MANAGEMENT_INTERNAL，显存管理器内部错误）。
> 正确做法是**一次加几层**慢慢试，并且盯着体检页里的显存占用，**别超过 85%**

如果换了更大的模型跑不动，把层数调小甚至设成 `0`（完全用 CPU）就行。
另外注意：**视觉模型**（主模型 + mmproj 视觉投影器那种）显存占用会顶到接近满格，
**可能越过 85% 安全线**，那种组合能不能跑要自己权衡。

## 三之二、怎么写小说

首页进「写小说」，点右上角「新建小说」，起个名字）。
它会按模板建好：

```
novels\<作品名>\
  设定卡.md              人物、世界观、文风 —— 整本书的锚
  单元01\大纲.md         这个单元要发生什么，含分节计划
  单元01\第01节.md       正文，一节一个文件（每单元 8 节）
  单元01\第02节.md
  ...
  单元02\ ...  单元03\ ...
```

页面左边是文件树，右边可以直接看和改，`Ctrl+S` 保存。

**推荐的使用顺序**（这也是模板里写的）：

1. 先在 `设定卡.md` 里把人物、世界观、**文风要求**填好 —— 文风那段最影响成品好不好看。
2. 填 `单元01\大纲.md`，**先把单元结尾写死**，中间才不容易写飞。
3. 去「对话」页，把**设定卡 + 大纲 + 让写第几节**一起贴进去，让它只写这一节。
4. 写好贴回 `第NN节.md`，再在大纲的「本节摘要」里留三五行。
5. 写下一节时，把摘要一起贴过去 —— 小模型上下文有限，不这么做它很快就"失忆"。

> 一句话：**别让它一口气写一整章**，一节一节推，每节都自己看一遍再往下走。

## 四、怎么加技能

所谓"技能"，就是 `app\skills\` 里一个**只用标准库**的 Python 脚本。

规矩很简单：

1. 脚本放在 `app\skills\` 里，比如 `app\skills\mytool.py`。
2. **只允许在 `work\` 目录里读写文件**，别的地方一律不许碰。
3. 需要读系统信息就调 `Get-CimInstance` / `nvidia-smi` 这类命令，
   **任何一条命令失败就跳过那一项，不许整个脚本崩掉**。
4. 输出用 UTF-8 打印一段 JSON 到标准输出，工作台会原样转给页面。
5. 在工作台 `app\workbench.py` 里加一个 `/api/xxx` 接口去调它（照着 `/api/status` 抄）。

参考实现就是 `app\skills\status.py`，里面有注释说明每一段在干嘛。

## 五、出问题了怎么办

### 双击 `启动.bat` 一闪而过 / 里面报一堆错

看窗口里的中文提示。如果提示是"找不到 py\python.exe"之类，
说明文件没拷全，重新把整个文件夹拷一遍。

### 提示 "等了 120 秒还没有就绪" / 模型服务起不来

按顺序试：

1. **关掉占显卡的程序**（游戏、浏览器里的视频、剪辑软件）。
2. **少给显卡几层**：`set PORTABLE_AI_GPULAYERS=12`
3. **完全用 CPU 跑**：`set PORTABLE_AI_GPULAYERS=0`（慢，但一定能起来）
4. **换另一个后端**：`set PORTABLE_AI_BACKEND=vulkan`
5. **多等一会儿**：`set PORTABLE_AI_WAITTIMEOUT=240`（这个盘读模型慢，120 秒有时不够）

### 换模型之后卡在"正在加载"很久

正常。这个盘冷读一个 2.3 GB 的模型要 1~4 分钟，换模型还要先把旧的停掉。
页面会一直显示进度，加载完自己就变了。**别关那个黑窗口**，关了模型服务也跟着停。

如果超过 5 分钟还没好，去看「模型管家」页有没有报错，
或者 `work\model_server.log` 里最后几行写了什么。

### 一开始能聊，过一会儿就卡住 / 整机很卡

内存不够。模型自己就要 1~2 GB，浏览器也很能吃。
把不用的程序关掉。体检页会告诉你内存用了多少、还剩多少。

### 蓝屏了

先别慌，重启后项目文件不会坏。看体检页和蓝屏记录：

- 如果是在**加载模型的时候**蓝屏，几乎肯定是显存被榨干了 —— 参考上面第三节，
  把 `--gpulayers` 调小。
- 想确认原因，可以先看系统里的蓝屏转储文件（一般在系统盘的
  `Windows\Minidump\` 目录下，需要管理员权限才能读）；
  多数情况不需要查这个，按上一条把 `--gpulayers` 调小即可。

### 关掉窗口后，发现还有 koboldcpp 在跑

正常情况下关窗口会一起收掉。万一没收干净，按 `Ctrl+Shift+Esc` 打开任务管理器，
找到 `koboldcpp` 结束掉就行。它不写注册表，结束后除了显存什么都不会留下。

### 页面打不开（显示"无法连接"）

看那个黑窗口还在不在。窗口在但页面打不开，可能是 8000 端口被别的程序占了，
换一台电脑或者关掉占用 8000 端口的程序。

### 实测记录（在一个 4 GB 显存的机器 + USB 移动盘上测的，仅供参考）

> 下面的数字跟硬件强相关，换台电脑会不一样，**别当性能预期**。

| 项目 | 结果 |
|---|---|
| 对话速度 | 约 3~7 字/秒（22 层给显卡） |
| 首个字出现 | 1~4 秒 |
| 显存占用 | 约 2.5 GB |
| 模型加载 | **1~4 分钟**（移动盘冷读慢；热缓存时明显更快） |
| 换模型总耗时 | 约 240 秒（含后端回退的一次尝试） |
| 关思考模式 | 写小说时用 `/no_think`，实测有效；`chat_template_kwargs` 这种方式无效 |

### 已知的小毛病

- 体检里的"磁盘速度测试"会被正在跑的模型干扰 —— 同一张盘，
  闲着测 34 MB/s，模型忙时测出 **4 MB/s**。所以"固态还是机械"这个结论
  在模型加载完之后测才准，结果缓存 7 天。
- **`koboldcpp` 启动时会把约 600 MB 运行库解包出来**（它是 PyInstaller 打包的单文件程序）。
  解包目录放在系统盘临时目录下的 `portable-ai-extract\`（系统盘通常比移动盘快得多），
  而且**每次启动前会自动清掉上次的残留**，所以不会堆积。
  > 这一条是踩出来的：早先反复强制结束 koboldcpp，解包残留没被清理，
  > 在系统临时目录里堆了 20 多个 `_MEI` 目录、**累计十几 GB**，
  > 把系统盘可用空间压掉了一大半。已清掉，并加了自动清理。
  > 实测解包放系统盘（固态）比放移动盘快将近一倍，所以现在放系统盘。
- 磁盘类型是**靠实测速度猜的**，不是系统报告。有些移动盘 Windows 也认不出类型。
- **对话页左上角的模型下拉框是给第二期留的**：换模型请去「模型管家」页。
  下拉框选不动不影响打字聊天（消息直接走 `/api/chat`）。
- 首页"说人话"用的是同一个 4B 模型，**偶尔会翻译错**。所以流程是
  "先给你看 → 你确认 → 才执行"，参数最后还有一道后端校验兜着。
